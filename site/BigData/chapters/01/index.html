01

왜 여러 컴퓨터가 필요할까요?

이 수업에서는 데이터를 처리하는 시스템을 만들고, 결과가 맞는지 직접 확인합니다.

기록이 늘면 처리 방법도 달라집니다.

주문 10건은 손으로 더할 수 있습니다. 주문이 계속 쌓이고 매일 마감 시각까지 계산해야 한다면, 저장 공간·메모리·처리 시간을 함께 고려해야 합니다.

  • 데이터: 주문 번호·금액·시각처럼 저장하고 계산할 수 있는 기록.
  • 빅데이터: 데이터의 규모와 처리 요구에 맞는 저장·계산 방법을 고민하는 문제.
학습용 비유 · 조별 과제

책 1,000권의 오탈자를 조원에게 나눠 찾으면 빨라질 수 있지만, 배분과 연락에도 시간이 듭니다. 분산 처리에도 통신과 작업 조정 비용이 있습니다.

한 대에서도 구조를 배울 수 있습니다.

실습에서는 내 PC 안에 실행 환경을 나누는 단위인 컨테이너를 여러 개 띄웁니다. 역할 간 통신을 관찰할 수 있지만, PC의 CPU·메모리 자체가 늘어나지는 않습니다.

컴퓨터를 늘려도 전체 속도를 제한하는 구간인 병목이 남을 수 있습니다. 이번 학기에는 “왜 나누는가?”에서 나아가 실제 시스템을 만들고 병목을 관찰합니다.

확인 질문 · 컴퓨터가 2대면 언제나 2배 빨라질까요?

아닙니다. 나눌 수 없는 작업, 데이터를 주고받는 시간, 한쪽에 몰린 작업이 있으면 기대만큼 빨라지지 않습니다. 이 수업에서는 결과뿐 아니라 실제 실행 구조도 살펴봅니다.

근거: 1장 실제 슬라이드 1–2, 5. 기본 용어와 조별 과제 비유는 이해를 돕기 위한 학습용 해설입니다.

02

주문 기록이 매출표가 되기까지

데이터 엔지니어링(Data Engineering, DE)은 데이터를 분석과 인공지능(AI)에 쓸 수 있도록 처리 흐름을 설계·구현·검증하는 일입니다.

“오늘 매출은 얼마인가?”에 답하려면 처음 생성된 기록인 원천 데이터를 가져와 정리하고 계산해야 합니다. 이렇게 연결된 처리 흐름이 데이터 파이프라인입니다.

수집에서 제공까지, 네 단계

각 단계를 선택해 역할을 확인하세요. 시각화는 학습용 모형입니다.

주문 예제 · 중복 기록은 어떻게 셀까요?

학습용 주문 기록 · A002는 같은 주문의 재전송
주문 번호금액기록 상태
A00110,000원정상
A00220,000원정상
A00220,000원같은 주문의 재전송

  1. 수집 · 원천에서 가져옵니다.

    쇼핑몰의 주문 기록 3행을 받습니다.

    • 행: 기록 하나.
    • 열: 주문 번호·금액 같은 항목.

  2. 변환 · 의미와 규칙을 맞춥니다.

    • 규칙: 주문 번호는 고유하며, 같은 번호의 재전송은 한 번만 계산.
    • 결과: 중복 A002를 제외하면 2건, 합계 30,000원.

    실제 업무에서도 중복 판단 기준을 먼저 정해야 합니다.

  3. 저장 · 다음에도 쓸 수 있게 남깁니다.

    원본과 정리한 결과를 구분해 보관합니다. 오류가 생기면 원본으로 다시 계산할 수 있습니다.

  4. 제공 · 사용하는 사람에게 전달합니다.

    날짜별 매출표를 분석가나 서비스에 전달합니다. 어떤 주문을 포함했는지도 설명할 수 있어야 합니다.

계산 뒤 확인할 세 가지

  • 누락: 빠진 주문이 없는가?
  • 재실행: 다시 실행해도 같은 기준인가?
  • 복구: 중단 후 처리를 재개할 수 있는가?

저장소도 목적에 따라 다릅니다.

  • 데이터 레이크: 다양한 데이터를 폭넓게 보관하는 저장소입니다.
  • 데이터 웨어하우스: 분석하기 좋게 정리한 데이터를 다루는 저장 체계입니다.

확인 질문 · 위 명세에 맞는 결과는 무엇인가요?

근거: 1장 실제 슬라이드 2–3. 주문표와 계산 결과는 강의 목표를 설명하는 학습용 예제이며 실습 실행 결과가 아닙니다.

03

코드 다음에 물어야 할 네 가지

“실행됐다”에서 멈추지 않고, 무엇을 계산했고 어디서 실행됐으며 커져도 괜찮은지 설명합니다.

학습용 비유 · 공동 요리의 책임

함께 요리할 때는 조리뿐 아니라 역할 배분·품질 유지·완성품 확인도 필요합니다. 데이터 시스템에서도 아래 네 역량을 함께 익힙니다.

01 · 처리 구현

“어떤 입력으로 어떤 출력을 만들까?”를 코드로 표현합니다.

  • DataFrame: 열 이름과 자료형을 가진 표 형태의 데이터 구조.
  • SQL: 필요한 행이나 집계 결과를 요청하는 질의 언어.
  • 배치(Batch): 모인 데이터를 작업 단위로 처리하는 방식.
  • 스트리밍(Streaming): 계속 들어오는 데이터를 지속적으로 처리하는 방식.

02 · 분산 실행 이해

“이 계산은 어디에서 이루어질까?”를 봅니다.

  • Apache Spark: 여러 실행 자원으로 데이터 처리를 수행하는 엔진입니다.
  • PySpark: Python으로 Spark를 사용하는 인터페이스입니다.

코드 한 줄이 여러 실행 자원에 나뉘어 처리될 수 있습니다.

03 · 신뢰성과 확장성

  • 신뢰성: 반복 실행·오류 상황에서도 요구한 결과를 안정적으로 제공하는 성질.
  • 확장성: 데이터·작업 증가에 자원과 처리 방식을 조정해 대응하는 성질.

주문이 100배 늘거나 작업을 다시 실행해도 괜찮은지 확인합니다.

04 · AI 협업과 검증

AI가 만든 코드도 개발자가 검증하고 채택 이유를 설명해야 합니다.

  • 명세: 입력 규칙과 기대 결과를 적은 기준.
  • 스키마(Schema): 열 이름·자료형 등 데이터 구조의 정의. 금액이 숫자인지 문자열인지도 여기에 해당합니다.

Spark에서 역할과 데이터 조각 구분하기

Spark 실행을 읽는 네 단어
단어실제 역할조별 계산에 빗대면
Driver애플리케이션의 실행을 조정하는 프로세스계산 계획을 세우고 결과를 받는 조장
Executor데이터 처리 작업을 수행하는 프로세스배정된 계산을 수행하는 조원

Shuffle다음 계산에 필요한 기준으로 데이터를 실행 자원 사이에 재분배하는 과정담당 기준이 바뀌어 문제지를 다시 나누기
Worker와 Executor 구분하기

Worker는 계산 자원을 제공하고 Executor를 실행합니다. Executor는 실제 데이터 처리 작업을 수행하는 프로세스입니다. 두 역할의 관계는 2장에서 실습합니다.

더 알아보기 · 실행을 살펴보는 도구는 무엇인가요?
  • Spark UI: 작업 상태와 실행 정보를 보는 웹 화면입니다.
  • 실행계획(Execution Plan): Spark가 계산을 어떤 연산 순서로 수행하려는지 나타냅니다. DataFrame의 explain()으로 계획을 살펴볼 수 있습니다.
  • Join: 공통 키를 기준으로 표를 연결하는 연산입니다. 예를 들어 주문표와 상품표를 상품 번호로 연결합니다.

이전 수업의 관련 용어도 함께 연결해 보세요.

  • Hadoop: 분산 데이터 저장·처리 기술군입니다.
  • HDFS: 파일을 여러 컴퓨터에 나누어 저장하는 시스템입니다.
  • MapReduce: 나누어 계산하고 결과를 모으는 처리 모델입니다.

여기서는 배경 이름만 연결하고, 별도 강의자료가 없는 세부 구현은 다루지 않습니다.

확인 질문 · Partition은 컴퓨터 한 대를 뜻하나요?

아닙니다. Partition은 데이터 조각입니다. 하나의 실행 자원이 여러 조각을 차례로 처리할 수 있습니다. 데이터 조각 수와 컴퓨터 수를 같은 것으로 생각하지 마세요.

근거: 1장 실제 슬라이드 4–5, 10. 용어의 쉬운 정의와 비유는 학습용 보충입니다.

05

Docker는 실습을 위한 준비 도구입니다.

친구의 PC에서는 되는데 내 PC에서는 안 된다면, 코드를 보기 전에 실행 환경이 같은지 확인해야 합니다.

재현 가능한 환경은 같은 설정으로 다시 실행할 수 있게 구성한 환경입니다. 수업에서는 Windows PC의 Docker Desktop과 WSL2를 사용합니다.

학습용 비유 · 실험 키트

실험 재료와 조립 설명서를 맞추듯, 이미지와 설정 파일로 시작 조건을 맞춥니다. PC 자원·네트워크는 다를 수 있어 실행 결과는 별도로 확인해야 합니다.

환경을 만드는 도구와 구성 요소

  • WSL2: Windows에서 Linux 환경을 실행하는 기반.
  • Docker: 실행 환경을 컨테이너로 관리하는 도구.

06

“맞는 값”과 “괜찮은 구조”를 함께 봅니다.

AI는 코드·테스트 초안과 오류 분석을 돕습니다. 정확성·확장성·성능을 확인하고 선택의 이유를 설명하는 일은 개발자의 책임입니다.

학습용 비유 · 계산기 답을 검산하기

계산기에 중복 주문을 입력하면 계산은 맞아도 매출은 틀립니다. AI 코드도 입력과 계산 기준이 맞는지 사람이 검산해야 합니다.

검증은 세 단계로 진행합니다.

  1. 문제와 명세를 적습니다.

    “1부터 100까지의 정수를 각각 한 번 더한다. 입력 열은 정수형 id, 기대 결과는 5,050이다.”처럼 입력과 결과를 구체화합니다.

  2. 사람이 코드를 읽습니다.

    범위의 끝값이 포함되는지, 모든 데이터를 한곳에 모으는지, 잘못된 입력을 어떻게 처리하는지 확인합니다.

  3. 실행·테스트·관찰로 확인합니다.

    작은 입력의 정답과 비교하고, Spark UI와 실행계획에서 실제 실행을 봅니다. 작은 예제 성공이 100배 규모의 성능을 보장하지는 않습니다.

학습용 코드 비교 · 같은 5,050, 다른 데이터 이동

코드를 읽기 전에
  • 실행 위치: spark가 준비된 PySpark 환경. PowerShell용 명령이 아닙니다.
  • SparkSession: Spark 기능을 사용하는 진입점으로, 아래 코드에서는 spark라는 이름을 사용합니다.
  • 준비 방법: 실제 환경 구성과 배포 프로그램 실행은 2장에서 진행합니다.

A · 원본 전체를 Driver로 가져와 더하기

df = spark.range(1, 101, 1, 4)
rows = df.collect()
total = sum(row["id"] for row in rows)
print(total)
  • range(1, 101, 1, 4): 1부터 100까지 1씩 증가하는 값을 4개 Partition으로 구성합니다. 끝값 101은 포함하지 않습니다.
  • collect(): 모든 행을 Driver로 가져옵니다.
  • sum: 가져온 값을 Driver의 Python에서 더합니다.

확인할 점: 원본이 커지면 모든 행이 Driver 메모리에 모이는 구조가 문제가 될 수 있습니다.

B · Spark에서 합계를 계산한 뒤 작은 결과 받기

from pyspark.sql import functions as F

df = spark.range(1, 101, 1, 4)
result = df.agg(F.sum("id").alias("total"))
row = result.first()
print(row["total"])
  • agg: 집계 연산을 표현합니다.
  • F.sum("id"): id 열을 합산합니다.
  • alias("total"): 결과 열 이름을 total로 붙입니다.
  • first(): 결과의 첫 행을 Driver로 가져옵니다. 이 예제는 그룹 없이 전체 합계를 계산하므로 결과가 한 행입니다.

확인할 점: 이 예제는 합계 한 행을 받습니다. 실제 집계 단계·데이터 이동은 실행계획에서 확인해야 합니다.

예상 결과: 5,050

두 코드의 예상값은 100 × 101 ÷ 2 = 5,050입니다. 손계산으로 확인한 값이며, 실제 Spark 실행 기록은 아닙니다.

코드를 적는 시점과 계산하는 시점

  • Transformation: 데이터를 어떻게 바꿀지 표현하는 연산입니다. 위 B의 agg는 집계를 표현합니다.
  • Action: 결과를 요청하거나 저장하는 등 계산을 수행하게 하는 연산입니다. B의 first()는 결과를 요청하며, A의 collect()도 Action입니다.

Spark에서는 코드를 적는 순서와 실제 데이터 계산 시점을 구분하는 습관이 필요합니다.

더 알아보기 · collect()는 항상 잘못된 코드인가요?

작은 결과를 의도적으로 가져올 때는 사용할 수 있습니다. 기준은 “몇 행, 몇 바이트가 Driver에 모이는가?”입니다.

  • 다른 수집 방식: toPandas()도 데이터를 Driver의 pandas 표로 가져옵니다.
  • Python 반복문: 큰 데이터를 한곳에 모아 순차 처리하는지 확인합니다.
  • 그룹별 집계: 그룹 수가 많으면 집계 결과도 커질 수 있습니다.
  • 성능 판단: 같은 조건에서 시간과 자원 사용을 측정해야 합니다.
