3. Docker 확인 · 2~3장에 사용

Windows에서는 Docker Desktop 공식 설치 안내에 따라 WSL 2 기반 Linux 컨테이너 환경을 준비합니다. 이미 설치되어 있다면 Docker Desktop을 열고 Engine이 실행될 때까지 기다립니다.

  • 성공 기준: docker version에 Client와 Server가 모두 나오고, 운영체제 값은 linux, Compose 설정 검사는 오류 없이 끝납니다.

02

같은 주문은 한 번만 계산하기

같은 주문이 여러 번 수집될 수 있습니다. 모든 행의 금액을 더하면 중복 주문도 매출에 포함됩니다. 이 예제에서는 A002와 A003의 중복 행으로 중복 제거 규칙을 확인합니다.

학습용 비유 · 영수증 번호 대조

같은 영수증이 두 장 있어도 판매는 한 번입니다. 번호는 같은데 금액이 다르면 한 장을 임의로 버리지 않고 확인해야 합니다.

입력 계약

  • 열: order_id,order_date,amount 순서.
  • 주문 번호: 빈 값은 오류. 양끝 공백은 제거.
  • 날짜: ISO 날짜를 읽어 YYYY-MM-DD로 저장.
  • 금액: 음수가 아닌 정수 원 단위.

중복·실패 규칙

  • 동일 ID·날짜·금액: 한 건으로 합침.
  • 동일 ID·다른 날짜나 금액: 충돌 오류로 종료.
  • 잘못된 입력: 결과 파일을 교체하기 전에 실패.
  • 재실행: 정렬한 동일 결과를 저장.

실행 위치: bigdata-practice 폴더의 PowerShell.

python apps/order_pipeline.py
Get-Content output/orders-clean.csv
Compare-Object (Get-Content expected/orders-clean.csv) (Get-Content output/orders-clean.csv)
$LASTEXITCODE
  • 결과 파일 비교: Compare-Object에 차이 행이 없으면 텍스트가 같습니다.
  • 프로그램 종료 확인: $LASTEXITCODE는 마지막 Python 프로세스의 종료 코드이며 정상은 0입니다. 차이 비교 자체의 성공 여부를 이 변수로 판단하지 않습니다.
INPUT_ROWS=5
UNIQUE_ORDERS=3
DUPLICATE_ROWS=2
TOTAL_AMOUNT=35000

위 값은 제공 입력의 예상 출력입니다. 실제 출력에는 결과 파일 위치도 나옵니다. WSL·macOS·Linux에서는 python3 apps/order_pipeline.py 뒤 diff expected/orders-clean.csv output/orders-clean.csv로 비교할 수 있습니다.

코드가 수행하는 네 단계

  1. 수집: csv.DictReader가 열 이름을 키로 가진 행을 읽습니다.
  2. 변환: 날짜·정수 변환과 중복/충돌 검사를 수행하고 주문 ID를 키로 보관합니다.
  3. 저장: ID순으로 임시 파일을 완성한 뒤 결과 파일로 교체합니다. 입력 파일은 읽기만 합니다.
  4. 제공: 정리된 CSV와 행 수·총액을 출력하여 사람이 예상 결과와 대조합니다.

직접 바꿔 확인하기

원본 입력을 보존하고 실험용 사본을 만들어 편집합니다.

Copy-Item data/orders.csv output/orders-test.csv
notepad output/orders-test.csv
python apps/order_pipeline.py --input output/orders-test.csv --output output/orders-test-clean.csv
$LASTEXITCODE
  • 같은 행 추가: 입력·중복 수만 증가하고 총액은 같습니다.
  • A002의 금액을 한 행에서만 변경: conflicting order_id A002 오류와 종료 코드 1. 결과를 갱신하지 않습니다.
  • 금액을 문자·음수로 변경: 변환·범위 오류. 입력 규칙 위반을 조용히 건너뛰지 않습니다.
  • 동일 명령 재실행: 주문 ID순으로 정렬한 결과가 같아야 합니다.
확인 질문

입력이 100배가 되어도 이 코드로 처리할 수 있을까요? 고유 주문을 Python 사전에 모두 보관하므로 고유 주문 수가 늘면 메모리 사용량도 늘어납니다. 큰 입력을 분산 처리하려면 데이터 분할 방법과 중복 제거 비용을 고려해야 합니다.

이 보충 실습의 프로젝트 이름은 knut-public-spark입니다. 2장 제공 실습의 Worker 1·2 이름과 8080/4040 포트는 사용하지 않습니다. 성능 측정 중에는 다른 학습 환경을 종료해 CPU·메모리 경합을 줄입니다.

1. 이미지와 local[2] 계산

실행 위치: compose.yaml이 있는 폴더의 PowerShell.

docker compose pull
docker compose run --rm --no-deps --entrypoint /opt/spark/bin/spark-submit spark-client --master "local[2]" /opt/spark/apps/sum_app.py
$LASTEXITCODE

예상 결과는 MASTER=local[2], SUM_1_TO_100=5050, CHECK=PASS, APP_STOPPED, 종료 코드 0입니다.

local[2]는 하나의 Java 실행 환경(JVM) 안에서 작업 스레드 두 개를 쓰는 모드입니다. 클러스터 Worker 두 개의 등록 여부는 다음 단계에서 검사합니다.

이 실습은 spark:4.1.3-scala2.13-java21-python3-ubuntu 이미지를 사용합니다. 태그는 Docker 공식 이미지 목록에 등록되어 있습니다. manifest unknown 오류가 나면 태그·레지스트리 주소를 확인합니다. 다른 버전을 쓰면 버전을 기록하고 각 실행 단계를 다시 확인합니다.

2. Worker 두 개 시작·등록 확인

docker compose up -d --scale spark-worker=2
docker compose ps
docker compose exec spark-client python3 /opt/spark/apps/check_cluster.py --workers 2
$LASTEXITCODE

ALIVE_WORKERS=2 TOTAL_CORES=2와 REGISTRATION_CHECK=PASS를 확인합니다. 검사기는 Master의 상태 JSON을 읽어 등록을 기다립니다. Master UI · localhost:28080의 ALIVE Worker 수도 2개여야 합니다.

healthy는 Master HTTP 응답 여부입니다. 등록 검사가 통과해도 Driver로 되돌아오는 연결과 실제 계산은 다음 단계에서 확인해야 합니다.

3. 클러스터에 앱 제출

docker compose exec spark-client bash /opt/spark/apps/submit.sh sum_app.py --wait-seconds 120
$LASTEXITCODE

MASTER=spark://spark-master:7077와 합계 5050을 확인합니다. UI_WAIT_SECONDS=120이 나오면 별도 브라우저에서 Driver UI · localhost:24041를 엽니다. 터미널은 관찰 대기 중이므로 다음 앱을 겹쳐 실행하지 않습니다.

  • Executors: Driver 행을 제외하고 계산 Executor와 할당 Core를 기록합니다.
  • Jobs / Stages: range의 입력 Partition 4개와 부분 합계·최종 합계 구조를 확인합니다.
  • 출력의 explain: Spark가 세운 물리 실행계획입니다. 출력 계획과 UI의 실제 실행 정보를 함께 읽습니다.
  • 종료: APP_STOPPED와 종료 코드 0을 확인합니다. 종료 후에는 이 Driver UI가 닫힙니다.
확인 질문

입력 Partition이 4개인데 Core가 2개라면 네 작업을 모두 동시에 실행할까요? 동시에 실행할 수 있는 작업 수는 배정된 Core에 제한됩니다. 입력 분할 수와 동시에 사용할 자원을 구분해 기록하세요.

4. Worker 하나로 같은 답 확인

docker compose up -d --scale spark-worker=1
docker compose exec spark-client python3 /opt/spark/apps/check_cluster.py --workers 1
docker compose exec -e TOTAL_EXECUTOR_CORES=1 spark-client bash /opt/spark/apps/submit.sh sum_app.py --wait-seconds 120

같은 입력과 합계를 유지하면서 가용 자원을 줄입니다. 숫자 100개의 실행 시간만으로 성능 차이를 판단하기는 어렵습니다. 다음 절을 진행하거나 종료 절차를 따릅니다.

Compose 전체 설정 · 계산 앱 전체 코드 · 제출 스크립트 전체 코드 · 2장 해설

client 모드와 local[N]의 의미: Spark 4.1.3 공식 제출 안내. Standalone의 Worker·Core 구성: Spark 4.1.3 Standalone 문서.

04

입력 문장이 집계 표로 바뀌는 과정

3장에서 배운 단어 집계 연산을 보충 입력 파일로 실행합니다. 입력은 Client 컨테이너에만 연결하므로 local[2]로 실행합니다. 클러스터의 Worker에는 이 파일이 연결되어 있지 않습니다.

학습용 비유 · 문장 카드를 단어별로 모으기

문장을 단어 카드로 자르고 같은 단어끼리 모아 셉니다. 실제 코드는 문자열 열을 배열로 나눈 뒤, 배열 원소를 여러 행으로 펼치고 집계합니다.

실행 위치: 같은 PowerShell. 앞 앱의 APP_STOPPED 이후. Client가 실행 중인 상태에서 아래를 실행합니다.

docker compose exec spark-client /opt/spark/bin/spark-submit --master "local[2]" /opt/spark/apps/wordcount_app.py
$LASTEXITCODE
Get-ChildItem output/wordcounts

예상 결과는 WORDCOUNT_CHECK=PASS, APP_STOPPED, 종료 코드 0입니다. 출력의 단어 표는 아래와 같습니다.

제공 입력의 예상 집계
wordcount
spark3
data2
pipeline1

Parquet는 같은 열의 값을 모아 저장하는 파일 형식입니다. Spark는 지정 경로에 데이터를 나누어 담은 part 파일과 성공 표시를 만듭니다. Get-ChildItem으로 이 출력 폴더의 파일 목록을 확인합니다.

입력에서 출력까지의 연산

  1. read.text: 한 줄을 문자열 value 한 행으로 읽습니다. 빈 줄도 살펴봅니다.
  2. split: 하나 이상의 공백을 기준으로 단어 배열을 만듭니다.
  3. explode · alias: 배열의 원소를 각각 word 행으로 펼칩니다.
  4. where: 빈 단어를 제외합니다. 대소문자나 문장부호는 바꾸지 않습니다.
  5. groupBy · count: 같은 단어를 모아 횟수를 계산합니다. 재배치인 Shuffle이 필요할 수 있습니다.
  6. orderBy: 횟수 내림차순, 동률이면 단어 오름차순으로 화면을 정렬합니다.
  7. write · read: Parquet로 저장하고 다시 읽어 예상 CSV와 비교합니다. 저장 후 행의 순서가 유지된다고 가정하지 않습니다.

재실행과 입력 변경

기존 결과를 보존하도록 기본 저장 모드는 errorifexists입니다. 같은 실습을 다시 실행하려면 새 출력 경로를 지정합니다.

docker compose exec spark-client /opt/spark/bin/spark-submit --master "local[2]" /opt/spark/apps/wordcount_app.py --output /opt/spark/lab-output/wordcounts-run2

입력을 바꾸면 expected/wordcounts.csv의 예상값도 직접 계산해 바꿉니다. 예를 들어 Spark와 spark는 서로 다른 단어로 집계됩니다. 표기를 통일하려면 먼저 어떤 표기를 같은 단어로 볼지 정합니다.

정답을 고정하고 자원을 바꾸기

입력·연산·정답 확인 규칙을 고정하고 성능을 비교합니다. 작은 입력으로 코드와 설정을 확인한 뒤 PC 자원에 맞춰 입력을 늘립니다. 숫자는 spark.range로 생성하므로 큰 입력 파일을 따로 준비하지 않습니다.

1. 작은 입력으로 실행 경로 확인

실행 위치: compose.yaml이 있는 폴더의 PowerShell. 앞 앱의 APP_STOPPED를 확인한 뒤 실행합니다.

1부터 1,000,000까지의 예상 합은 500000500000입니다. end는 포함하지 않는 끝값입니다. 각 실행 시간과 CHECK=PASS를 확인한 뒤 종료까지 기다립니다.

2. 기록할 입력·측정 방법 고정

  • 수업 규모: --end 1000000001이면 1~10억, 예상 합은 500000000500000000입니다.
  • 작은 PC: 더 작은 end를 유지해도 됩니다. 비교할 모든 조건의 end를 같게 바꾸고 기록표에도 반영합니다.
  • 고정값: Partition 128, 반복 3회, Executor당 1 Core·512m. 제출 파일에서 동적 할당과 AQE(실행 중 계획 조정)는 꺼서 비교 조건을 단순하게 둡니다.
  • 측정 범위: 집계 DataFrame 정의 직전부터 first가 결과를 돌려줄 때까지. Docker 시작·SparkSession 준비·계산 후 UI 대기는 제외합니다.
  • 첫 실행: JVM 준비·코드 생성·Executor 할당 비용이 섞일 수 있습니다. 세 실행 모두 기록하며 첫 값을 숨기지 않습니다. 캐시는 사용하지 않습니다.

3. Worker와 Core를 함께 1 → 2 → 4 → 8로 늘리기

PowerShell에서 아래 블록을 조건마다 실행합니다. 먼저 $workers = 1, 다음은 2, 4, 8로 바꿉니다. 앞 앱의 APP_STOPPED를 확인한 뒤 다음 조건을 실행하세요. 실행하지 못한 조건은 기록표에서 미측정으로 남깁니다.

4. Worker 8개에서 Core 상한만 2로 고정

2/2 조건의 화면을 놓쳤다면 그 조건으로 되돌려 동일 명령에 --wait-seconds 120을 추가해 관찰합니다. 관찰용 재실행의 시간은 앞 측정값과 섞지 않고 따로 표시합니다.

apps/order_pipeline.py · CSV 파이프라인 전체
"""Small, synthetic CSV pipeline. Python standard library only."""
import argparse
import csv
from datetime import date
from pathlib import Path
import tempfile

ROOT = Path(__file__).resolve().parents[1]
FIELDS = ["order_id", "order_date", "amount"]


def clean_orders(source):
    unique = {}
    input_rows = 0
    with source.open(encoding="utf-8-sig", newline="") as stream:
        reader = csv.DictReader(stream)
        if reader.fieldnames != FIELDS:
            raise ValueError("CSV header must be order_id,order_date,amount")
        for line, row in enumerate(reader, start=2):
            input_rows += 1
            if None in row or any(row[key] is None for key in FIELDS):
                raise ValueError(f"line {line}: expected three columns")
            order_id = row["order_id"].strip()
            if not order_id:
                raise ValueError(f"line {line}: empty order_id")
            order_date = date.fromisoformat(row["order_date"].strip()).isoformat()
            amount = int(row["amount"])
            if amount < 0:
                raise ValueError(f"line {line}: amount must be nonnegative")
            record = (order_date, amount)
            if order_id in unique and unique[order_id] != record:
                raise ValueError(f"line {line}: conflicting order_id {order_id}")
            unique[order_id] = record
    return unique, input_rows


def run(source, output):
    if source.resolve() == output.resolve():
        raise ValueError("input and output must be different files")
    orders, input_rows = clean_orders(source)
    output.parent.mkdir(parents=True, exist_ok=True)
    temporary = None
    try:
        with tempfile.NamedTemporaryFile(
            mode="w", encoding="utf-8", newline="", dir=output.parent,
            prefix="orders-", suffix=".tmp", delete=False,
        ) as stream:
            temporary = Path(stream.name)
            writer = csv.writer(stream, lineterminator="\n")
            writer.writerow(FIELDS)
            for order_id, (order_date, amount) in sorted(orders.items()):
                writer.writerow([order_id, order_date, amount])
        temporary.replace(output)
    finally:
        if temporary is not None:
            temporary.unlink(missing_ok=True)
    print(f"INPUT_ROWS={input_rows}")
    print(f"UNIQUE_ORDERS={len(orders)}")
    print(f"DUPLICATE_ROWS={input_rows - len(orders)}")
    print(f"TOTAL_AMOUNT={sum(amount for _, amount in orders.values())}")
    print(f"OUTPUT={output}")


def main():
    parser = argparse.ArgumentParser(description=__doc__)
    parser.add_argument("--input", type=Path, default=ROOT / "data/orders.csv")
    parser.add_argument("--output", type=Path, default=ROOT / "output/orders-clean.csv")
    args = parser.parse_args()
    try:
        run(args.input, args.output)
    except (ValueError, OSError) as error:
        parser.exit(1, f"ERROR: {error}\n")


if __name__ == "__main__":
    main()
apps/check_cluster.py · Worker 등록 검사 전체
"""Wait for the requested number of live one-core workers; no PySpark needed."""
import argparse
import json
import time
from urllib.error import URLError
from urllib.request import urlopen


def main():
    parser = argparse.ArgumentParser(description=__doc__)
    parser.add_argument("--workers", type=int, required=True)
    parser.add_argument("--timeout", type=int, default=90)
    args = parser.parse_args()
    if args.workers < 1 or args.timeout < 1:
        parser.error("workers and timeout must be positive")
    deadline = time.monotonic() + args.timeout
    observed = "master not reached"
    while time.monotonic() < deadline:
        try:
            with urlopen("http://spark-master:8080/json/", timeout=3) as response:
                status = json.load(response)
            live = [worker for worker in status["workers"] if worker["state"] == "ALIVE"]
            cores = sum(int(worker["cores"]) for worker in live)
            observed = f"ALIVE_WORKERS={len(live)} TOTAL_CORES={cores}"
            if len(live) == args.workers and cores == args.workers:
                print(observed)
                print("REGISTRATION_CHECK=PASS")
                return
        except (URLError, TimeoutError, OSError, ValueError, KeyError) as error:
            observed = str(error)
        time.sleep(1)
    parser.exit(1, f"REGISTRATION_CHECK=FAIL: {observed}\n")


if __name__ == "__main__":
    main()

apps/wordcount_app.py · 단어 집계 전체
"""Count the supplied small text fixture, save Parquet, then read it back."""
import argparse
import csv
from pathlib import Path


def small_counts(frame):
    rows = frame.limit(101).collect()
    if len(rows) > 100:
        raise ValueError("this teaching check supports at most 100 distinct words")
    return {row["word"]: row["count"] for row in rows}


def main():
    parser = argparse.ArgumentParser(description=__doc__)
    parser.add_argument("--input", default="/opt/spark/lab-data/words.txt")
    parser.add_argument("--expected", default="/opt/spark/lab-expected/wordcounts.csv")
    parser.add_argument("--output", default="/opt/spark/lab-output/wordcounts")
    args = parser.parse_args()
    with Path(args.expected).open(encoding="utf-8-sig", newline="") as stream:
        expected = {row["word"]: int(row["count"]) for row in csv.DictReader(stream)}
    from pyspark.sql import SparkSession, functions as F

    spark = SparkSession.builder.appName("Public-Wordcount").getOrCreate()
    try:
        spark.sparkContext.setLogLevel("WARN")
        if not spark.sparkContext.master.startswith("local["):
            raise ValueError("use --master local[2]: files are mounted only in the client")
        lines = spark.read.text(args.input)
        words = lines.select(
            F.explode(F.split(F.col("value"), r"\s+")).alias("word")
        ).where(F.col("word") != "")
        counts = words.groupBy("word").count()
        ordered = counts.orderBy(F.desc("count"), F.asc("word"))
        print("INPUT_LINES")
        lines.show(truncate=False)
        print("WORD_ROWS")
        words.show(truncate=False)
        print("WORD_COUNTS")
        ordered.show(truncate=False)
        ordered.explain()
        if small_counts(ordered) != expected:
            raise ValueError("word counts differ from the expected CSV")
        ordered.write.mode("errorifexists").parquet(args.output)
        restored = spark.read.parquet(args.output)
        if small_counts(restored) != expected:
            raise ValueError("Parquet round-trip check failed")
        print("WORDCOUNT_CHECK=PASS", flush=True)
        print(f"PARQUET_OUTPUT={args.output}", flush=True)
    finally:
        spark.stop()
    print("APP_STOPPED", flush=True)


if __name__ == "__main__":
    main()

def main():

    parser.add_argument("--end", type=int, default=1_000_001)
    parser.add_argument("--partitions", type=int, default=128)
    parser.add_argument("--repetitions", type=int, default=3)
    parser.add_argument("--wait-seconds", type=int, default=0)
    args = parser.parse_args()
    if not 2 <= args.end <= 4_294_967_296:
        parser.error("end must be 2..4294967296 (keeps the sum within signed 64-bit)")
    if args.partitions < 1 or args.repetitions < 1 or args.wait_seconds < 0:
        parser.error("partitions/repetitions must be positive; wait must be nonnegative")
    from pyspark.sql import SparkSession, functions as F

    spark = SparkSession.builder.appName("Public-Worker-Benchmark").getOrCreate()
    try:
        spark.sparkContext.setLogLevel("WARN")
        context = spark.sparkContext
        print(f"MASTER={context.master}", flush=True)
        print(f"APP_ID={context.applicationId}", flush=True)
        print(f"REQUESTED_CORES={context.getConf().get('spark.cores.max', 'unset')}", flush=True)
        print(f"END_EXCLUSIVE={args.end}", flush=True)
        print(f"PARTITIONS={args.partitions}", flush=True)
        print(f"REPETITIONS={args.repetitions}", flush=True)
        numbers = spark.range(1, args.end, 1, args.partitions)
        expected = (args.end - 1) * args.end // 2
        durations = []
        for repeat in range(1, args.repetitions + 1):
            started = time.perf_counter()
            total = numbers.agg(F.sum("id").alias("total")).first()["total"]
            elapsed = time.perf_counter() - started
            if total != expected:
                raise ValueError(f"expected {expected}, received {total}")
            durations.append(elapsed)
            print(f"RUN_{repeat}_SECONDS={elapsed:.6f}", flush=True)
        print(f"SUM_RESULT={total}", flush=True)
        print(f"MEDIAN_SECONDS={statistics.median(durations):.6f}", flush=True)
        print("CHECK=PASS", flush=True)
        print(f"UI_WAIT_SECONDS={args.wait_seconds}", flush=True)
        time.sleep(args.wait_seconds)
    finally:
        spark.stop()
    print("APP_STOPPED", flush=True)


if __name__ == "__main__":
    main()
