01 / 개념원본 PDF 3, 21–22쪽

소켓은 프로그램이 사용하는 통신 끝점입니다

프로그램은 운영체제에 요청해 데이터를 보내고 받습니다. 이때 통신의 끝점으로 사용하는 자원이 소켓(socket)입니다. 소켓을 만들고 사용하는 작업을 요청하는 함수들을 소켓 API라고 부릅니다.

socket()은 소켓을 만들고 식별자를 반환합니다. Windows에서는 이를 SOCKET sock에, Linux에서는 int fd에 저장합니다. 이 식별자는 IP 주소나 포트 번호, 메모리 주소와 구분해야 합니다.

구분역할예
소켓 식별자프로그램 안에서 특정 소켓을 지정Windows의 sock, Linux의 fd
IP 주소통신할 네트워크 인터페이스의 주소를 지정루프백 주소 127.0.0.1
포트 번호TCP/UDP에서 통신 끝점을 구분하는 데 사용예: TCP 포트 9000

TCP 통신에서는 소켓 생성 뒤에 주소 설정, 연결 또는 연결 수락, 송수신이 이어집니다. 이번 프로그램은 이 중 생성과 정리만 실행하므로 상대 주소와 포트, 별도의 서버가 필요하지 않습니다.

소켓 생성이번 실습주소 설정·연결이후 학습송수신이후 학습소켓 닫기이번 실습
02 / 프로그램 구조원본 PDF 3, 13, 21, 26–28쪽

정상 흐름을 먼저 읽고, 실패하는 지점을 찾습니다

두 운영체제 모두 소켓을 생성하고 사용이 끝나면 닫습니다. Windows에서는 그 앞뒤에 Winsock 사용을 시작하고 끝내는 단계가 추가됩니다. 아래는 모든 호출이 성공했을 때의 실행 순서입니다.

오류 처리는 이 흐름의 각 호출 직후에 들어갑니다. 초기화가 실패하면 소켓을 만들 수 없고, 생성이 실패하면 닫을 소켓이 없습니다. 따라서 반환값을 확인한 뒤 다음 단계로 이동해야 합니다.

프로그램의 실행 순서

main()에서 준비 → 생성 → 정리를 수행합니다. 실패한 경우에는 오류를 출력하고, 확보한 자원을 정리한 뒤 종료합니다.

소스 파일의 작성 순서

헤더 포함 → 보조 함수 정의 → main() 순서로 배치합니다. 파일에서 먼저 보이는 보조 함수가 자동으로 먼저 실행되는 것은 아닙니다.

03 / 사용 준비원본 PDF 13–20, 27쪽

Windows에서는 Winsock을 먼저 초기화합니다

Winsock은 Windows의 소켓 API입니다. WSAStartup()은 사용할 버전을 요청하고 초기화 결과를 구조체에 기록합니다. Linux의 기본 소켓 API에는 이 초기화 단계가 없습니다.

Windows · C / main 내부 발췌
WSADATA wsa;
int result = WSAStartup(MAKEWORD(2, 2), &wsa);
if (result != 0) {
    fprintf(stderr, "WSAStartup failed: %d\n", result);
    return 1;
}

wsa의 자료형은 WSADATA이며, 구조체 변수입니다. &wsa는 그 변수의 주소이므로, 함수가 호출한 쪽의 구조체에 결과를 쓸 수 있습니다. MAKEWORD(2, 2)는 하위 바이트에 주 버전, 상위 바이트에 부 버전을 넣습니다.

초기화 성공 후 LOBYTE(wsa.wVersion)과 HIBYTE(wsa.wVersion)으로 합의된 버전의 두 부분을 읽습니다. 아래 전체 코드는 두 값이 2인지 확인한 뒤 소켓을 만듭니다. 버전이 맞지 않아 중단하더라도 성공한 초기화는 정리해야 합니다.

WSAStartup() 실패의 원인은 반환값 자체에 있습니다. 이 경우 WSAGetLastError()로 다시 조회하지 않습니다. 성공한 초기화 한 번에는 WSACleanup() 한 번을 대응시킵니다.

04 / 소켓 생성원본 PDF 21–25쪽

socket()의 세 인자로 통신 방식을 지정합니다

사용할 주소 체계와 데이터 전달 방식을 정하면 운영체제가 소켓을 생성합니다. 이번 실습은 IPv4의 TCP 소켓을 만듭니다.

Windows · C / 초기화 성공 뒤의 발췌
SOCKET sock = socket(AF_INET, SOCK_STREAM, 0);
만들 소켓주소 체계소켓 타입프로토콜
IPv4 TCPAF_INETSOCK_STREAM0 또는 IPPROTO_TCP
IPv6 TCPAF_INET6SOCK_STREAM0 또는 IPPROTO_TCP
IPv4 UDPAF_INETSOCK_DGRAM0 또는 IPPROTO_UDP
IPv6 UDPAF_INET6SOCK_DGRAM0 또는 IPPROTO_UDP

TCP는 연결을 맺은 뒤 순서 있는 바이트 스트림을 전달합니다. UDP는 데이터그램 단위를 유지하지만 도착·순서·중복 방지를 보장하지 않습니다. IPv4와 IPv6는 주소 체계이고, TCP와 UDP는 전송 프로토콜이므로 서로 다른 선택입니다.

소켓 호출 조합해 보기

보충 체험 · 선택에 맞는 코드 표현만 만듭니다.

SOCKET sock = socket(AF_INET, SOCK_STREAM, 0);

반환값은 운영체제에 맞는 타입에 저장합니다

환경저장할 변수성공실패
WindowsSOCKET sock유효한 소켓 핸들INVALID_SOCKET
Linuxint fd0 이상의 파일 디스크립터-1

Windows의 SOCKET을 임의로 int에 넣으면 값이 잘릴 수 있습니다. Linux에서는 0도 유효한 fd이므로 if (!fd) 대신 if (fd == -1)로 실패를 검사합니다.

05 / 오류 처리원본 PDF 4–12쪽

실패 확인, 원인 확인, 정리를 나누어 작성합니다

오류 처리는 메시지를 출력하는 데서 끝나지 않습니다. 함수가 실패했는지 판단하고, 원인을 보관한 뒤, 다음 동작을 결정하는 과정입니다. 실패한 함수의 결과를 그대로 다음 단계에 넘기지 않아야 합니다.

함수성공실패실패 원인을 읽는 곳
Windows WSAStartup()00이 아닌 값반환값 자체
Windows socket()유효한 SOCKETINVALID_SOCKETWSAGetLastError()
Windows closesocket() / WSACleanup()0SOCKET_ERRORWSAGetLastError()
Linux socket()0 이상의 fd-1errno
Linux close()0-1errno

함수마다 실패를 알리는 규약이 다릅니다. 원본은 이를 오류 확인이 필요 없는 함수, 반환값 자체가 오류 코드인 함수, 반환값과 별도 오류 코드를 함께 확인하는 함수로 분류합니다. 이 장에서는 위 표에 나온 함수들의 규약을 기준으로 작성합니다.

Windows: 오류 코드를 저장한 뒤 메시지로 바꿉니다

socket()이 INVALID_SOCKET을 반환하면 WSAGetLastError()로 현재 스레드의 Winsock 오류 코드를 읽습니다. 다른 API가 오류 상태를 바꿀 수 있으므로 실패를 확인한 직후 변수에 저장합니다.

Windows · C / 오류 코드 저장과 전달 · 발췌
SOCKET sock = socket(AF_INET, SOCK_STREAM, 0);
if (sock == INVALID_SOCKET) {
    int error = WSAGetLastError();
    report_error("socket", error);
    /* 호출한 쪽에서 Winsock 정리와 종료를 이어서 처리한다. */
}

여기서 report_error()는 아래 전체 코드에서 정의하는 보조 함수입니다. "socket"은 실패한 작업의 이름, error는 원인을 나타내는 숫자입니다. 이 함수는 FormatMessageA()로 숫자에 해당하는 시스템 메시지를 찾아 출력합니다.

  1. 코드 보관error = WSAGetLastError()
  2. 문자열 요청FormatMessageA()
  3. 오류 출력fprintf(stderr, …)
  4. 메시지 해제LocalFree(message)

stderr는 오류 출력 스트림입니다. 일반 결과와 구분해 오류를 기록할 때 사용합니다. 메시지 변환에 실패하더라도 저장한 숫자 코드는 출력할 수 있습니다.

원본의 err_quit()과 err_display() 역시 직접 정의한 보조 함수입니다. 출력과 종료를 어느 함수에서 맡는지 구분해 읽습니다.

오류 출력 함수하는 일호출 후 흐름
원본 err_quit()오류 메시지 출력exit(1)로 프로세스 종료
원본 err_display()오류 메시지 출력호출한 곳으로 복귀
보충 report_error()전달받은 오류 코드와 설명 출력호출한 곳에서 자원 정리와 종료 결정
FormatMessageA의 인자와 포인터 읽기
설정 또는 값이 코드에서의 역할
FORMAT_MESSAGE_FROM_SYSTEMWindows가 제공하는 메시지에서 오류 설명을 찾습니다.
FORMAT_MESSAGE_ALLOCATE_BUFFER문자열을 담을 공간을 API가 할당하게 합니다.
FORMAT_MESSAGE_IGNORE_INSERTS별도 삽입 인자 없이 메시지를 읽습니다.
(LPSTR)&message새 문자열의 주소를 받을 포인터 변수의 주소입니다. ALLOCATE_BUFFER 모드에서 요구하는 전달 방식입니다.
반환값 length0이면 메시지 변환 실패입니다. 이때는 숫자 오류 코드를 출력합니다.
LocalFree(message)이 옵션으로 할당받은 문자열을 사용 후 해제합니다.

char *message = NULL;은 메시지가 놓일 주소를 저장할 변수를 만든 것입니다. 아직 메시지용 메모리를 확보한 것은 아닙니다.

&message를 전달하면 API가 message 변수에 새 공간의 주소를 기록할 수 있습니다. 이 공간은 malloc()으로 만들지 않았으므로 free() 대신 LocalFree()로 해제합니다.

Linux: errno를 저장하고 strerror()로 설명을 읽습니다

Linux에서는 소켓 함수가 실패하면 errno에 원인이 기록됩니다. errno는 함수가 아니며, 이 코드에서는 그 값을 정수 변수에 복사합니다. strerror(error)는 저장한 숫자에 해당하는 설명 문자열을 반환합니다.

Ubuntu · C17 / main 내부 발췌
int fd = socket(AF_INET, SOCK_STREAM, 0);
if (fd == -1) {
    int error = errno;
    fprintf(stderr, "socket: %d (%s)\n", error, strerror(error));
    return 1;
}

성공한 호출이 이전 오류 상태를 지워 준다고 가정하지 않습니다. errno만 보고 실패를 판단하지 말고, 먼저 fd == -1인지 확인합니다.

Windows의 메시지

FormatMessageA()에 버퍼 할당을 요청했으므로 출력 후 LocalFree()로 돌려줍니다.

Linux의 메시지

strerror()가 돌려준 문자열은 직접 할당한 공간이 아닙니다. 내용을 수정하거나 free()하지 않습니다.

06 / 자원 정리원본 PDF 7, 17–18, 25–26쪽

성공한 단계까지만 정리합니다

Winsock 초기화와 소켓 생성은 서로 다른 단계입니다. 종료할 때는 실제로 확보한 자원을 확인하고 정리합니다. Windows에서는 소켓을 먼저 닫고 Winsock 사용을 마칩니다.

어디까지 진행했나요?확보한 자원정리 순서
WSAStartup 실패이 호출로 시작된 Winsock 사용 없음오류를 알리고 종료
WSAStartup 성공 → socket 실패Winsock 사용만 시작됨WSACleanup()
WSAStartup 성공 → socket 성공Winsock 사용과 소켓closesocket(sock) → WSACleanup()
Linux socket 성공소켓close(fd)

closesocket()은 소켓 하나를 닫습니다. WSACleanup()은 Winsock 사용을 종료합니다.

예를 들어 초기화에 한 번 성공한 뒤 소켓을 세 개 만들었다면, 세 소켓을 각각 닫고 그 초기화에 대응하는 WSACleanup()을 한 번 호출합니다.

실패 위치에 따른 흐름

보충 체험 · 아래 버튼은 실제 API 호출 없이 제어 흐름을 보여 줍니다.

    아래 Windows 전체 코드에서는 status에 프로그램의 최종 성공·실패를 기록합니다. 초기화가 성공한 뒤 오류가 생기면 status = 1로 바꾸고 공통 정리 지점까지 진행합니다. 이렇게 하면 중간에서 바로 종료해 정리를 빠뜨리는 일을 줄일 수 있습니다.

    이번 예제는 기본 블로킹 소켓을 생성한 뒤 바로 닫습니다. 연결된 소켓의 남은 데이터, 논블로킹 동작, linger 설정은 이후 통신 단계에서 다룹니다. 닫은 식별자는 이전 소켓을 가리키는 값으로 다시 사용하지 않습니다.

/* MSVC는 pragma, MinGW/Dev-C++는 빌드 명령의 -lws2_32로 링크한다. */
#ifdef _MSC_VER
#pragma comment(lib, "ws2_32.lib")
#endif

/* 오류 코드를 먼저 저장한 뒤 전달한다. 이 함수는 종료하지 않는다. */
static void report_error(const char *where, int error)
{
    char *message = NULL;
    DWORD length = FormatMessageA(
        FORMAT_MESSAGE_ALLOCATE_BUFFER | FORMAT_MESSAGE_FROM_SYSTEM
            | FORMAT_MESSAGE_IGNORE_INSERTS,
        NULL, (DWORD)error, 0, (LPSTR)&message, 0, NULL);

    if (length != 0 && message != NULL) {
        fprintf(stderr, "%s: %d (%s)\n", where, error, message);
    } else {
        fprintf(stderr, "%s: %d (message unavailable)\n", where, error);
    }

    if (message != NULL) {
        LocalFree(message);
    }
}

int main(void)
{
    WSADATA wsa;
    int status = 0;

    /* 실패 코드는 WSAStartup의 반환값 자체에 있다. */
    int result = WSAStartup(MAKEWORD(2, 2), &wsa);
    if (result != 0) {
        report_error("WSAStartup", result);
        return 1;
    }

    printf("Winsock %u.%u initialized\n",
        (unsigned)LOBYTE(wsa.wVersion), (unsigned)HIBYTE(wsa.wVersion));

    /* 이 예제는 Winsock 2.2를 사용한다. 성공한 초기화는 정리한다. */
    if (LOBYTE(wsa.wVersion) != 2 || HIBYTE(wsa.wVersion) != 2) {
        fprintf(stderr, "Winsock 2.2 is required\n");
        status = 1;
    } else {
        /* 소켓 자원만 생성한다. 연결이나 데이터 송수신은 하지 않는다. */
        SOCKET sock = socket(AF_INET, SOCK_STREAM, 0);
        if (sock == INVALID_SOCKET) {
            int error = WSAGetLastError();
            report_error("socket", error);
            status = 1;
        } else {
            puts("TCP socket created (not connected)");

            /* 생성에 성공한 소켓만 닫는다. 오류는 즉시 저장한다. */
            if (closesocket(sock) == SOCKET_ERROR) {
                int error = WSAGetLastError();
                report_error("closesocket", error);
                status = 1;
            } else {
                puts("Socket closed");
            }
        }
    }

    /* 초기화가 성공한 모든 경로는 이곳에서 한 번 정리한다. */
    if (WSACleanup() == SOCKET_ERROR) {
        int error = WSAGetLastError();
        report_error("WSACleanup", error);
        status = 1;
    } else {
        puts("Winsock cleaned up");
    }

    return status;
}

    개념과 실행 흐름 확인

    WSAStartup이 0이 아닌 값을 반환하면 무엇을 출력해야 하나요?

    그 반환값 자체가 오류 코드입니다. 다른 Winsock 함수처럼 WSAGetLastError로 다시 조회하지 않습니다.

    Windows socket()이 실패했을 때 첫 번째로 할 일은?

    INVALID_SOCKET인지 확인한 뒤 WSAGetLastError()를 호출해 코드부터 저장합니다. 이후 출력과 정리를 수행합니다.

    err_display()를 호출하면 오류가 해결되나요?

    아닙니다. 메시지를 출력하고 돌아올 뿐입니다. 계속 실행할지, 재시도할지, 자원을 정리하고 끝낼지는 호출한 코드가 결정합니다.

    FormatMessage가 할당한 문자열과 strerror의 문자열을 같은 방법으로 해제하나요?

    아닙니다. ALLOCATE_BUFFER로 받은 문자열은 LocalFree로 해제합니다. strerror가 돌려준 문자열은 직접 해제하지 않습니다.

    초기화에는 성공했지만 socket()에 실패하면 무엇을 닫나요?

    소켓은 생성되지 않았으므로 closesocket을 호출하지 않습니다. 성공한 초기화에 대응해 WSACleanup을 호출합니다.

    SOCKET sock을 int에 저장해도 되나요?

    Windows에서는 SOCKET 타입을 유지합니다. Linux의 파일 디스크립터 int와 같은 크기라고 가정하지 않습니다.

    socket(AF_INET6, SOCK_DGRAM, 0)은 무엇을 만들까요?

    IPv6 주소 체계의 기본 UDP 소켓을 만듭니다. protocol의 0은 기본 프로토콜 선택입니다.

    Linux socket()이 0을 반환하면 실패인가요?

    성공입니다. 0도 유효한 파일 디스크립터일 수 있습니다. 실패값은 -1입니다.

    TCP 소켓을 만들면 상대와 연결된 건가요?

    아닙니다. 통신에 쓸 자원을 만든 상태이며 주소 지정·연결 등의 후속 단계가 필요합니다.

    -lws2_32는 소스 코드 어디에 쓰나요?

    C 코드가 아니라 MinGW의 링크 옵션에 넣습니다. MSVC의 pragma comment와 도구를 혼동하지 않습니다.

    .o 파일이 생겼다면 빌드와 실행이 모두 끝난 건가요?

    아직입니다. 오브젝트를 라이브러리와 링크해 실행 파일을 만들어야 합니다. 만들어진 실행 파일을 시작하는 것이 실행입니다.

    헤더에 함수 선언이 있는데도 링크 오류가 나는 이유는 무엇인가요?

    헤더는 컴파일에 필요한 선언을 제공합니다. 호출할 함수의 구현과 연결하려면 링크 설정도 필요합니다. MinGW의 Winsock 예제에서는 -lws2_32를 지정합니다.

    11 / 실습 파일독립 실행형 C 예제

    운영체제에 맞는 소스를 선택합니다

    페이지에 표시한 전체 코드와 같은 내용의 파일입니다. Windows에서는 Winsock 예제를, Ubuntu에서는 POSIX 예제를 내려받습니다. 두 파일 모두 UTF-8이며 추가로 작성해야 할 헤더 파일은 없습니다.
